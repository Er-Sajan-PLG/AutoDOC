# Documentation policy

## Scope
AutoDOC indexes possible project documents in `CATALOG-A`, `CATALOG-B`, and `CATALOG-C`.
An index entry is not evidence that a project has actually implemented a control. Select applicable
entries, assign owners and instance IDs, and record non-applicability with reasons.

## Authority
`docs/.doc-sync-map.yaml` maps authoritative sources to generated targets and human reviews.
Generation is deterministic and read-only in check mode. Do not hand-edit generated files;
change the source then run `python scripts/doc-sync/generate-all.py`.
For human-review mappings, update the listed target *after* reviewing the source change.
The checker can prove co-change, not semantic correctness; CODEOWNERS and branch protection
must be enabled by repository administrators for actual approval enforcement.

## Metadata
Controlled Markdown (`docs/`, `CONTROL/`, `EXAMPLE-PROJECT/docs/`, `examples/ai-agent-example/docs/`, `examples/local-tools-example/docs/`, root agent-context files and living-state files)
uses the fields in `CONTROL/metadata/FRONT-MATTER-SCHEMA.json`. Templates under
`TEMPLATES/` are uninstantiated examples; give each instantiated document a unique ID.
Generated docs have stable build-independent metadata; drift, rather than age, validates them.

## Limitations
No script proves that a security audit, backup, SBOM attestation, or human review happened.
Evidence packs need real CI or service evidence; never fabricate them. The bounded examples and Python/Markdown/manifest extractors do not parse arbitrary-language
contracts; see `docs/00-governance/ENGINE-COVERAGE.md` for the actual supported sources.
The root agent context documents record human intent and must be reviewed by a person.

CI uploads an unsigned pack of the **test suite it actually ran**, declared project component,
material hashes and documentation health. It does not attest to a signed build, full dependency
resolution, security, backup success or external compliance. Packs are run artifacts, not
committed evidence files; a tagged release requires a `vX.Y.Z` tag at the same commit and a
present `LICENSE` (Apache-2.0 since 2026-10-01).

The initial 2026-09-26 metadata on human-authored starter documents is an authoring baseline,
not owner approval. Those files are marked draft pending owner review. New unverified scaffolds
use `1970-01-01` as a sentinel so freshness warns until a real review updates the metadata.

## Enforced starter matrix

| Artifact | Source | Local/CI check | Effect |
| --- | --- | --- | --- |
| Mapped generated targets | Declared source files | `engine.py drift` | Fail when bytes differ |
| Mapped human-owned targets | Changed file paths | `engine.py impact --base SHA` | Fail block-level co-change; warn others |
| Living state | Changed mapped code paths | `engine.py impact --base SHA` | Require all three files in PR |
| Changelog | User-facing example code/routes | `engine.py impact --base SHA` | Fail when missing in PR |
| Controlled frontmatter | Controlled Markdown | `frontmatter_validator.py` | Fail malformed metadata and unknown IDs |
| Declared ownership | Controlled Markdown + ownership matrix | `check_ownership.py` | Fail unknown/out-of-scope owner |
| Offline links/phrases/key markers | Markdown and staged files | `guards.py` | Fail broken local links/forbidden phrases/private-key marker |
| Inventories/relationships | Controlled frontmatter | Generated bytes + schema check | Fail orphan IDs or stale derived views |
| Freshness | Human `last_verified` + SLA | `engine.py freshness` | Fail overdue critical, warn others |
| Catalog templates | Catalog indices | `library.py --check` | Fail missing or modified generated variants |
| Catalog schema and rules | Catalog indices + `CATALOG-RULES.json` | `check_catalog.py`, `build_catalogs.py --check` | Fail invalid entries, undetectable predicates, facts with no consumer, and index drift |
| Declared context | `autodoc.toml` + `CONTEXT-MODEL.json` | `context.py` | Fail unknown phases, kinds, audiences, facts and inert severity rules |
| Applicability decisions | `autodoc.toml` + profile | `recommend.py --check` | Report or fail applicable core types by declared phase; advisory while no phase is declared |
| Fact vocabulary | `profile.py` detectors | `check_catalog.py` | Fail a fact with no detector, no limits, or no consumer |
| Enforcement policy | `CONTEXT-MODEL.json` + `autodoc.toml` | `enforce.py` | Report or fail each check family at the declared phase's severity, minus recorded baseline |
| Adoption baseline | `autodoc-baseline.json` | `enforce.py` | Suppress recorded findings, report stale entries, never silently pass a new one |
| Exit codes | any AutoDOC command | `docs/reference/EXIT-CODES.md` | `0` success, `1` findings, `2` usage or configuration error |
| Instantiated starter docs | Required sections | `completeness.py` | Fail unfilled starter docs |
| Approved title-only stubs | Controlled Markdown | `stub_check.py` | Fail approved docs with no section or content beyond the title; drafts warn |
| Event triggers | `CONTROL/metadata/TRIGGERS.json` + workflows | `triggers.py --check` | Fail an undeclared workflow, an unresolvable declared command, or a required check a filter could stop from reporting |
| External links (scheduled) | Controlled Markdown | `check_external_links.py` | Warn-only: rate-limited, capped, run on the schedule, never part of the pull-request gate |

Other requested controls (SBOM signing, API extraction in arbitrary languages, model evaluation,
external compliance evidence and automatic issue creation) need real project integrations and
credentials/ownership; no check is claimed for them here. Do not configure a green CI badge to
imply those controls have run.

AutoDOC now maps its own catalog indices and CI workflow files into generated references;
changes to sync or control scripts require review of `docs/05-architecture/AUTODOC-ARCHITECTURE.md`,
and catalog edits require `docs/00-governance/ADOPTION.md` to be reviewed. The ownership
matrix checks metadata assignments; GitHub branch protection must still be configured separately.

The bounded demo environment file requires per-key descriptions; declared alerts must link to
a real repository runbook. A generated Mermaid relationship view is derived from actual
frontmatter, source mappings and catalog templates; it is not a semantic architecture proof.
